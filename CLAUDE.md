# UserIdentity

.NET 10 auth service on PolyzenKit, EF Core 10 (Microting MySQL provider, snake_case names) and NATS JetStream.

## Layout
- `Application/Core/<Feature>/{Commands,Queries,Events,ViewModels,Shared}`. Handlers implement PolyzenKit interfaces such as `ICreateItemCommandHandler<,>`, `IUpdateItemCommandHandler<,>` or `IEventHandler<>`. Handlers and repositories are registered by name scan. `Shared/` classes (`AppRoleNames`, `UserMessages`, `CleanupBatch`) aren't registered: handlers use them statically. Tokens are issued by the command handlers in `Tokens/Commands` (`CreateAccessTokenCommandHandler`, `StartSessionCommandHandler`, `ExchangeRefreshTokenCommandHandler`).
- `Domain/<Table>` holds entities, their `<Table>Limits` classes and their DTO projections, which derive from the entity and set the audit fields inline; response-only DTOs go in the feature's `ViewModels`, and external API shapes (`GoogleRecaptchaResponseDto`) in `Infrastructure`. Entities apply their limits with `[MaxLength]`. Identity's tables have no entity of ours, so `UserLimits` covers `users` and `user_details`, and `IdentityUserConfiguration` and `IdentityRoleConfiguration` apply the limits to Identity's columns.
- `Common/Enums` holds `RequestSource`, `Common/Errors/ErrorMessages` every error text a client sees, and `Common/Validation/ValidationPatterns` the email format that sign-up, invites and the wait list share, and the scope actions a role claim accepts.
- The service's settings are sealed classes with init-only properties. Each sits next to what reads it: the `Shared/` folder of its feature, `GoogleRecaptchaSettings` in `Infrastructure/ExternalServices`, and `PasswordHashingSettings` beside `PasswordHashingFilter`. They carry their own rules, as annotations (`[Range]`) or `IValidatableObject`. `Program.cs` and `Extensions.cs` bind them with PolyzenKit's `AddAppSetting<T>()`, which checks those rules and registers `IOptions<T>`; `PasswordHashingSettings` is only read, with `GetRequiredSetting<T>()`, to build the limiter.
- `Presentation/Endpoints` holds one static class per group (`UserEndpoints`, `RoleEndpoints`, ...), each mapping `MapApiGroup("<Name>")`, which gives the route, the tag and the scope entity. Each endpoint is one `internal static` method that fills the fields the server sets and calls one handler. `AdminApp.GetAsync` resolves the app an admin endpoint works on: the token's app, or the `X-App-Name` app for a global admin. `AdminApp.GetName` gives the role and user endpoints the token's app name, or null for a global admin.
- `PasswordHashingFilter` limits concurrent password hashes on the endpoints that hash. It's an endpoint filter because ASP.NET runs a global rate limiter before the per-IP policy, so requests over their own budget would take queue places from other clients.
- DbContexts are pooled, so `AppDbContext` holds no per-request state. It turns off EF's automatic savepoints, because every handler with a transaction rolls all of it back on failure. A handler that catches a failed save and carries on would need them.
- `Persistence/Repositories/Roles` reads Identity's roles, user roles and role claims in single queries (`IdentityRole` isn't a `BaseEntity`, so `RoleRepository` implements its interface directly).
- `UnitTests/Architecture/LayerDependencyTests` enforces which layer may use which. Fix the code rather than loosening it.
- `AddAppCleanups` registers PolyzenKit periodic deletes for expired refresh tokens, expired login tickets, expired password resets and unconfirmed users (`CleanupSettings`). They work in batches of `CleanupBatch.Size` (100), and the expiry cleanups delete with `ExecuteDeleteAsync`. The unconfirmed-user cleanup does nothing unless `RequireConfirmedAccount` is on; it frees the invite of the user's own app and deletes the Identity user, and foreign keys with cascading deletes remove the details, app links, refresh tokens and reset requests. Nothing is soft-deleted, so queries don't filter on `IsDeleted`.

## Messaging
- Sign-up and password reset add `UserMessages` to PolyzenKit's outbox (`ICreateItemCommandHandler<CreateOutboxMessageCommand, OutboxMessageViewModel>`) before their save or commit: sign-up on `useridentity.user.registered` (`WelcomeUser`), password reset on `useridentity.password-reset.requested` (`PasswordReset`). Subjects name what happened, so each event type has its own.
- `Infrastructure/Messaging` holds the two message handlers: one turns the message saying a code was verified into `CodeVerifiedEvent` (confirm the user, or verify the reset request), and `CallbackRequestedMessageHandler` turns `useridentity.callback.requested` into `UserRegisteredEvent`, which calls the app's callback. Only UserIdentity reads that subject; sign-up adds it only for `register-for-service` sign-ups to apps with a `CallbackUrl`.
- Handlers let exceptions through so PolyzenKit retries the message; `NoRecordException`, `InvalidDataException`, `RecordExistsException` and `IllegalOperationException` drop it.

## Apps and roles
- Roles are shared by all apps and named `<app>:<role>`, so admin endpoints are scoped in the handlers. Endpoints pass `AppName` (`AdminApp.GetName`), and handlers use `AppRoleNames` for role names (`AppRoleNames.GetAppRoleAsync` finds a role of the caller's app) and `IUserRegisteredAppRepository.IsUserRegisteredForAppAsync` for users, returning 404 for another app's records. Null means a global admin (`RoleSettings:GlobalAdminRole`). Registered apps are global admin only. Role names are stored in lower case on create and rename.
- App admins manage their own app's role scopes. Scope strings don't name an app, so this is safe only because tokens carry only `ForApp` roles; every scope-protected endpoint must act only on the caller's app, or also require a role app admins can't give. `CreateRoleClaimCommandHandler` refuses scopes on the global admin role (it's in every app's tokens) and lowercases resource and action, since scopes are compared case-sensitively against lowercase names; `DeleteRoleClaimCommandHandler` lowercases them too.
- Login and reset look up the user name before the email, so `RegisterUserCommand` lets a user name look like an email only when it matches the sign-up's own `UserEmail`. A blank `UserEmail` or `PhoneNumber` is stored as null, since `users.normalized_email` is unique.
- Accounts belong to the apps in `user_registered_apps`. `IUserRepository.GetUserDtoAsync` with an app name returns `null` for other apps' users, which is what makes login fail. `CreateAccessTokenCommandHandler` puts only `AppRoleNames.ForApp` roles and their scopes in login, sign-up and refresh tokens.
- Invite codes and wait list entries are keyed by `(AppId, UserEmail)`, and their endpoints resolve the admin's app with `AdminApp.GetAsync`. Invite lists filter by email (up to 100 characters) and applied status before counting and paging.
- An invite's optional `Role` is granted on sign-up, after the default role and in the same transaction. `CreateInviteCodeCommandHandler` accepts only an existing `ForApp` role that isn't an admin role (`AppRoleNames.IsAppAdminRole`, which counts `<app>:admin` as well as `RoleSettings:AdminRoles`), since app admins create invites and must not hand out admin. `RegisterUserCommandHandler` checks the invite whenever `InviteCode` is sent, not only when the app requires one, and answers a missing, wrong or used invite the same way. Only unused invites can be revoked.
- `PasswordResetSettings:MaxRequestsPerDay` counts the last `PasswordResetLimits.RequestCountWindow` of requests, so expired requests are deleted only that long after they expire.
- `users.normalized_email` is unique (`IdentityUserConfiguration`), and `UniqueViolationInterceptor` turns a race into a 400. `RefreshTokenEntity.Version` is a concurrency token, so the second of two simultaneous refreshes gets a 409.

## Commands
- Add a migration: run `dotnet ef migrations add <Name> --project UserIdentity/UserIdentity.csproj --output-dir Persistence/Migrations`. The tool builds the context with `Persistence/AppDbContextFactory`, which reads `DatabaseSettings` from `appsettings.json` and environment variables and applies the same options as the app (`UseAppMysql`). It needs a reachable MySQL (`ServerVersion.AutoDetect`), but no keys.
- When adding or changing endpoints, update `Readme.md`, and `UserIdentity/UserIdentity.http` when the endpoint is one of its flows. It holds only the main flows and uses only syntax that both Visual Studio and VS Code's REST Client support: file variables, `# @name` with `{{name.response.body.$...}}`, and `{{$timestamp}}` for unique names.

## Tests
- Tests use FakeItEasy, not Moq.
- Endpoint unit tests (`UnitTests/Presentation/Endpoints`) call the endpoint methods directly with faked handlers and an `ApiRequest` from `TestUtils/ApiRequestFactory`, which sets the claims, headers, `RoleSettings` and the group's `ScopeEntityMetadata`. The HTTP integration tests live under `IntegrationTests/Presentation/Endpoints`.
- `TestingWebAppFactory` starts MySQL and NATS, fakes Google reCAPTCHA with `StubHttpServer` and turns rate limiting off. Before the host starts it creates the sending service's stream and UserIdentity's own (`NatsTestHelper.CreateStreamsAsync`), so the message handlers attach at once instead of backing off. It seeds a second app, `OtherApp`, for cross-app checks (`AppScopingTests`), and a third, `CallbackApp`, whose `CallbackUrl` points at the same stub. `TestUtils/StubHttpServer` is a local Kestrel server: tests set a response per path with `OnPost`, read what arrived from `Requests`, and clear both with `Reset`; anything else gets a 404. `TestDbHelper.CreateUserEntity` also links the user to `TestApp`.
- `SqlCommandCounter` counts each request's SQL commands by its `X-Request-Id`.
- `TestingWebAppFactory` builds one Respawner, and `BaseIntegrationTests` resets the database with it before each test, roles included, then adds `TestApp`'s admin role back. It must ignore `__EFMigrationsHistory`, or a second host re-runs every migration.
- Other tests' messages share the stream, so `NatsTestHelper.FindMessageAsync(subject, correlationId)` reads it with an ordered consumer and filters by correlation id; the helper also publishes the message saying a code was verified.
- Compare JSON values as text (`$"{jsonObject["error"]?["message"]}"`): `Assert.Equal(string, JToken)` passes for any value.
- `InviteOpenApiContractTests` exports the Development contract from a disposable InMemory host, with no broker or database.
- `UserIdentity.SmokeTests` runs the published image with no reference to the service. Kestrel limits can only be tested there, because TestServer doesn't enforce them. A request-size test must send every required field, or it stops at validation and shows nothing.
